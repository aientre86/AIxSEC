## Generative AI and Large Language Model Vulnerabilities

As organizations transition from static predictive models to Large Language Models (LLMs) and conversational interfaces, the threat landscape shifts toward natural-language manipulation, complex context interactions, and supply-chain vulnerabilities. The **[OWASP Top 10 for Large Language Model Applications (2025 Edition)](https://genai.owasp.org/llm-top-10/)** captures the ten most critical failure modes in production GenAI systems.

### Detailed Taxonomy of OWASP LLM Risks (2025)

| Risk ID & Category | Vulnerability Mechanics & Sub-Types | Architectural & Operational Mitigations |
| :--- | :--- | :--- |
| **[LLM01: Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)** | Attackers manipulate natural-language inputs to override system instructions and force unintended actions:<br>• **Direct (Jailbreaking):** Adversarial prompts entered directly by users to bypass safety rules.<br>• **Indirect:** Malicious instructions hidden inside external data (websites, emails, uploaded PDFs) ingested by the LLM. | • Enforce strict privilege separation between system instructions and untrusted external data.<br>• Apply least-privilege scoping to any backend tools.<br>• Deploy dedicated prompt-injection classifiers (e.g., [Llama Guard 3](https://huggingface.co/meta-llama/Llama-Guard-3-8B), [AWS Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/)). |
| **[LLM02: Sensitive Information Disclosure](https://genai.owasp.org/llmrisk/llm022025-sensitive-information-disclosure/)** | LLMs inadvertently expose PII, proprietary source code, credentials, or trade secrets present in training sets, unprotected RAG vector stores, or unredacted context windows. | • Scrub and anonymize training and RAG datasets prior to ingestion.<br>• Enforce strict Role-Based Access Control (RBAC) metadata filters at the vector retrieval layer.<br>• Deploy automated PII detection and redaction (e.g., [Microsoft Presidio](https://github.com/microsoft/presidio)). |
| **[LLM03: Supply Chain](https://genai.owasp.org/llmrisk/llm032025-supply-chain/)** | Compromised third-party pre-trained weights, poisoned fine-tuning datasets, malicious prompt templates, or insecure serialization formats (such as Python `pickle`) that execute arbitrary code upon loading. | • Ban `pickle` formats; standardize on **[SafeTensors](https://huggingface.co/docs/safetensors/)** (and ensure patched parsers/sandboxed Jinja templates if using **GGUF**).<br>• Verify cryptographic signatures ([Sigstore](https://www.sigstore.dev/)) and maintain an AI Bill of Materials (A-SBOM).<br>• Run static scanners ([ModelScan](https://github.com/protectai/modelscan)) before loading weights. |
| **[LLM04: Data and Model Poisoning](https://genai.owasp.org/llmrisk/llm042025-data-and-model-poisoning/)** | Adversaries manipulate pre-training, fine-tuning, or embedding data to inject backdoors, biases, or **vector black-hole attacks** (placing poisoned embeddings near the vector centroid to hijack similarity searches). | • Track end-to-end data provenance using ML-BOMs.<br>• Isolate training and fine-tuning jobs inside air-gapped or restricted network sandboxes.<br>• Monitor training loss convergence and run automated poisoning/trigger simulations. |
| **[LLM05: Improper Output Handling](https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/)** | Downstream web apps, databases, or microservices accept and execute raw LLM text without validation or encoding—triggering XSS, CSRF, SSRF, SQL injection, or Remote Code Execution (RCE). | • Treat all LLM completions as untrusted user input (Zero Trust).<br>• Validate responses against strict schemas ([Pydantic](https://docs.pydantic.dev/) or JSON Schema) before downstream consumption.<br>• Apply context-aware HTML/SQL escaping and Content Security Policies (CSP). |
| **[LLM06: Excessive Agency](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/)** | Granting an LLM agent **excessive functionality** (unneeded tools/shell access), **excessive permissions** (high-privilege ambient credentials), or **excessive autonomy** (executing state-changing actions without confirmation). | • Enforce the Principle of Least Agency by restricting tools to narrow, read-only, or parameterized functions.<br>• Execute API calls using downscoped, user-delegated OAuth tokens.<br>• Mandate Human-in-the-Loop (HITL) sign-off for irreversible actions. |
| **[LLM07: System Prompt Leakage](https://genai.owasp.org/llmrisk/llm072025-system-prompt-leakage/)** | Attackers extract hidden system instructions via adversarial probing, exposing backend database schemas, internal API parameters, or guardrail logic used to craft precision exploits. | • **Golden Rule:** Treat system prompts as behavioral guidance, *never* as security controls.<br>• Never store API keys, connection strings, or confidential rules in system prompts; use external secret managers (e.g., [HashiCorp Vault](https://www.vaultproject.io/)). |
| **[LLM08: Vector and Embedding Weaknesses](https://genai.owasp.org/llmrisk/llm082025-vector-and-embedding-weaknesses/)** | Exploiting flaws in how text is embedded and retrieved from vector databases—such as cross-tenant data leakage, metadata filter bypasses, or embedding inversion attacks. | • Enforce strict tenant and user-level partition isolation in vector databases.<br>• Validate authorization metadata filters deterministically outside the LLM.<br>• Monitor similarity-search query distributions for anomalous probing. |
| **[LLM09: Misinformation](https://genai.owasp.org/llmrisk/llm092025-misinformation/)** | Probabilistic hallucinations cause models to assert plausible-sounding falsehoods, leading to legal liability, faulty decisions, or reputational harm when users overrely on unverified outputs. | • Ground responses via Retrieval-Augmented Generation (RAG) anchored to verified enterprise sources.<br>• Implement automated contextual grounding checks and require human expert review for high-stakes outputs. |
| **[LLM10: Unbounded Consumption](https://genai.owasp.org/llmrisk/llm102025-unbounded-consumption/)** | Permitting uncontrolled, recursive, or oversized inference requests—enabling **Denial of Wallet (DoW)** financial exhaustion, compute denial of service, or high-volume model extraction. | • Enforce strict token caps on inputs and outputs.<br>• Implement per-user API rate limiting, financial budget circuit breakers, and maximum step limits on agent reasoning loops. |
